    Laboratorio: Elasticsearch en 3 nodos (LAN)

    Documento para una actividad de laboratorio.
    Objetivo: desplegar un clúster Elasticsearch de 3 nodos, cargar un dataset (CSV) y evaluar rendimiento en indexación y consultas, comparando el impacto de shards y réplicas.

    1. Resultados de aprendizaje

    Al finalizar, el alumnado será capaz de:

    • Desplegar un clúster Elasticsearch 8.x de 3 nodos en la misma LAN.
    • Generar y distribuir certificados y parámetros de seguridad mínimos (laboratorio).
    • Cargar un CSV a Elasticsearch con Bulk API.
    • Diseñar un benchmark de indexación y un benchmark de consultas con k6.
    • Interpretar resultados y justificar decisiones sobre número de shards y réplicas.

    2. Requisitos y entorno

    • 3 máquinas en la misma LAN (Ubuntu/Debian o equivalente).
    • Docker + Docker Compose instalados.
    • Puertos:
    • 9200/TCP (HTTP Elasticsearch)
    • 9300/TCP (transport entre nodos)
    • 5601/TCP (Kibana, opcional)
    • Dataset de laboratorio: covid_raw.csv (≈17 MB, ≈1.3M filas)

    IPs usadas en el laboratorio (ejemplo)

    • es01: 10.20.90.21
    • es02: 10.20.90.29
    • es03: 10.20.90.28

    3. Despliegue del clúster (3 nodos)

    3.1 Parámetros clave

    • cluster.name: mismo en los 3 nodos
    • node.name: distinto por nodo
    • network.host: IP local del nodo
    • discovery.seed_hosts: lista de IPs (los 3 nodos)
    • cluster.initial_master_nodes: lista de nombres de nodos (solo primer arranque)
    • Seguridad:
    • Para laboratorio, suele usarse HTTP sin TLS y transporte con TLS (recomendado), o todo sin TLS (más simple pero menos realista).

    En este laboratorio se documenta el flujo de generación de certificados con elasticsearch-certutil y su reparto por nodos.

    3.2 Verificación del clúster

    curl -u elastic:changeme http://10.20.90.21:9200/_cluster/health?pretty
curl -u elastic:changeme http://10.20.90.21:9200/_cat/nodes?v

    4. Carga del dataset (CSV → Bulk API)

    4.1 Esquema del CSV (cabecera)

    provincia_iso,sexo,grupo_edad,fecha,num_casos,num_hosp,num_uci,num_def

    4.2 Índices de prueba

    Se crean dos índices equivalentes para comparar shards:

    • covid_raw_s3: number_of_shards=3
    • covid_raw_s6: number_of_shards=6

    En ambos casos, para laboratorio: - number_of_replicas=1 (base) - mapping recomendado: - fecha: date - provincia_iso, sexo, grupo_edad: keyword - contadores: integer

    Nota: el número de shards solo se define al crear el índice. Las réplicas sí se pueden cambiar en caliente.

    4.3 Importación por bulk (script)

    Se usa un script de carga que: - convierte CSV a NDJSON para Bulk - parte en chunks - envía los bulk - mide tiempo y tasa

    (Ver apéndices en el DOCX para scripts completos.)

    5.1 Instalación de k6 (Ubuntu 24)

    5.2 Qué significa “worker” aquí

    En k6, workers = VUs (Virtual Users): concurrencia del cliente.
    Cada VU ejecuta iteraciones de consultas (con mezcla ponderada).

    5.3 Batería de consultas (tipo dashboard)

    Se mide una mezcla de consultas representativas: - series temporales (date_histogram) - top por provincia (terms + sum) - métricas agregadas - una consulta de detalle (hits)

    Parámetros del laboratorio: - REQUEST_CACHE=1 (caché de requests activada) - RANDOMIZE=0 (misma consulta repetida → escenario muy “cache-friendly”)

    6. Comparativa 1: shards (s3 vs s6) con réplicas=1 (baseline)

    Escenario baseline:
    - covid_raw_s3 (3 shards, replicas=1) vs covid_raw_s6 (6 shards, replicas=1)
    - Se prueba contra 3 coordinadores (cada nodo como endpoint HTTP) - Workers (VUs): 1,2,4,8 - Duración: 60s (warmup 20s)

    6.2 Interpretación didáctica

    • Más shards no garantiza mejor consulta.
    • Con consultas repetidas y caché caliente, el coste de coordinación (fan-out a shards + reduce/merge) pesa mucho.
    • En este dataset y mix, s3 tiende a dar más RPS y menor p95 que s6.

    7. Comparativa 2: réplicas en s3 (replicas=1 vs replicas=2) manteniendo s6 con replicas=1

    Nuevo escenario:
    - covid_raw_s3 pasa a number_of_replicas=2 (en un clúster de 3 nodos, cada shard queda con 1 primaria + 2 réplicas) - covid_raw_s6 se mantiene con replicas=1

    Cambio en caliente: 

    curl -u elastic:changeme -H 'Content-Type: application/json'   -X PUT http://10.20.90.21:9200/covid_raw_s3/_settings   -d '{"index":{"number_of_replicas":2}}'

    1 330.300 328.089 -0.67 4.671 4.607 -1.36
    2 629.406 624.144 -0.84 5.106 5.157 +0.99

    Lectura rápida (este laboratorio): - El cambio a replicas=2 en s3 tiene un efecto muy pequeño en este modo “cache-friendly”. - Es normal: si el cuello está en coordinación/CPU o en la propia naturaleza de la agregación, añadir copias no necesariamente mejora p95.

    8. Conclusiones principales (lo importante del laboratorio)

    8.1 Shards: por qué “más” no siempre es “mejor”

    • Cada consulta se ejecuta por shard y luego se fusiona.
    • Subir shards aumenta paralelismo, pero también:
    • overhead de coordinación
    • fan-out interno
    • coste de reduce/merge en agregaciones
    • Resultado típico (como el observado): s3 supera a s6 en throughput y p95 para consultas repetidas.

    8.2 Réplicas: cuándo ayudan realmente

    • Las réplicas aumentan la capacidad de lectura (pueden atender búsquedas desde copias).
    • En consultas repetidas con caché muy favorable, el impacto puede ser bajo.
    • En un escenario más realista suele notarse más:
    • REQUEST_CACHE=0
    • RANDOMIZE=1
    • consultas con filtros cambiantes y cardinalidad alta

    8.3 Recomendación pedagógica

    • Enseñar al alumnado a no “tocar shards” a ciegas.
    • Diseñar comparativas: 1) s3 vs s6 (shards) 2) s3 replicas=1 vs replicas=2 (réplicas) 3) repetir (1) y (2) con caché desactivada y consultas randomizadas

    9. Actividades propuestas para el alumnado

    1) Repetir el benchmark con: - REQUEST_CACHE=0 - RANDOMIZE=1 - y comparar si ahora réplicas ayudan más. 2) Encontrar el “sweet spot” de workers (VUs) donde RPS sube sin disparar p95. 3) Justificar una configuración final para un dashboard: - objetivo p95 < 100 ms - objetivo RPS mínimo (según requisitos)

    B.2 generate_certs.sh

    #!/usr/bin/env bash
set -euo pipefail

# Genera CA + certificados por instancia (PEM) usando elasticsearch-certutil dentro del contenedor.
# Requisitos en el host:
#  - Docker
#  - carpeta ./certs con instances.yml
#
# Nota AppArmor (Ubuntu): si te falla con docker-default, añade:
#   --security-opt apparmor=unconfined

ES_VERSION="${ES_VERSION:-8.19.9}"
CERTS_DIR="${CERTS_DIR:-$PWD/certs}"

mkdir -p "$CERTS_DIR"
test -f "$CERTS_DIR/instances.yml" || { echo "Falta $CERTS_DIR/instances.yml"; exit 1; }

docker run --rm -u 0:0 --security-opt apparmor=unconfined   -v "$CERTS_DIR:/certs"   "docker.elastic.co/elasticsearch/elasticsearch:${ES_VERSION}"   bash -c '
    set -e
    cd /usr/share/elasticsearch

    # CA
    bin/elasticsearch-certutil ca --silent --pem -out /certs/ca.zip
    (command -v unzip >/dev/null && unzip -o /certs/ca.zip -d /certs || (cd /certs && jar xf ca.zip))

    # Certs por instancia
    bin/elasticsearch-certutil cert --silent --pem       --ca-cert /certs/ca/ca.crt --ca-key /certs/ca/ca.key       --in /certs/instances.yml -out /certs/certs.zip
    (command -v unzip >/dev/null && unzip -o /certs/certs.zip -d /certs || (cd /certs && jar xf certs.zip))

    # Permisos para copiar fácilmente
    chmod -R a+rX /certs
  '

echo "[OK] Certificados generados en: $CERTS_DIR"
echo "Contenido esperado:"
echo "  certs/ca/ca.crt"
echo "  certs/es01/es01.crt + es01.key"
echo "  certs/es02/es02.crt + es02.key"
echo "  certs/es03/es03.crt + es03.key"

    E. Scripts para crear índices (s3 y s6) y ajustar réplicas

    E.1 create_covid_indices.sh

    #!/usr/bin/env bash
set -euo pipefail

ES="${ES:-http://10.20.90.21:9200}"
AUTH="${AUTH:-elastic:changeme}"

create_index () {
  local INDEX="$1"
  local SHARDS="$2"
  local REPLICAS="$3"

  curl -sS -u "$AUTH" -H 'Content-Type: application/json'     -X PUT "$ES/$INDEX" -d @- <<JSON
{
  "settings": {
    "number_of_shards": ${SHARDS},
    "number_of_replicas": ${REPLICAS},
    "refresh_interval": "1s"
  },
  "mappings": {
    "properties": {
      "provincia_iso": { "type": "keyword" },
      "sexo":          { "type": "keyword" },
      "grupo_edad":    { "type": "keyword" },
      "fecha":         { "type": "date" },
      "num_casos":     { "type": "integer" },
      "num_hosp":      { "type": "integer" },
      "num_uci":       { "type": "integer" },
      "num_def":       { "type": "integer" }
    }
  }
}
JSON
  echo "[OK] creado: $INDEX (shards=$SHARDS, replicas=$REPLICAS)"
}

# Recomendación: crear s3 y s6 con replicas=1 (baseline)
create_index covid_raw_s3 3 1
create_index covid_raw_s6 6 1

    E.2 set_replicas.sh

    #!/usr/bin/env bash
set -euo pipefail

ES="${ES:-http://10.20.90.21:9200}"
AUTH="${AUTH:-elastic:changeme}"
INDEX="${INDEX:-covid_raw_s3}"
REPLICAS="${REPLICAS:-2}"

curl -sS -u "$AUTH" -H 'Content-Type: application/json'   -X PUT "$ES/$INDEX/_settings"   -d "{"index": {"number_of_replicas": ${REPLICAS}}}"

echo "[OK] $INDEX replicas=$REPLICAS"
echo "[+] Esperando GREEN..."
curl -sS -u "$AUTH" "$ES/_cluster/health/$INDEX?wait_for_status=green&wait_for_no_relocating_shards=true&timeout=900s"

    F. Benchmark de indexación (CSV → Bulk)

    F.1 Script Bash (recomendado para el laboratorio): run_elastic_csv_benchmark_v4.sh

    #!/usr/bin/env bash
set -euo pipefail

# ============================================================
# Benchmark de carga CSV -> Elasticsearch (Bulk API)
# 6 ejecuciones: shards=(3,6) x workers=(1,2,4)
# Genera un CSV resumen con:
#   - tiempo de indexación
#   - docs/s
#   - MB/s (sobre NDJSON sin compresión)
#   - tiempo hasta GREEN tras activar replicas=1
#
# Uso:
#   AUTH="elastic:changeme" ./run_elastic_csv_benchmark_v4.sh covid_raw.csv
#
# Requisitos:
#   bash, python3, curl, gzip, split, xargs, awk, find
#
# Nota importante:
#   NO se usa la variable de entorno "GZIP" (gzip la interpreta como opciones).
#   En su lugar se usa USE_GZIP (0/1) y además se ejecuta gzip con "env -u GZIP".
# ============================================================

[[ -n "${BASH_VERSION:-}" ]] || { echo "Este script requiere bash. Ejecuta: bash $0 <csv>"; exit 1; }

CSV_PATH="${1:-covid_raw.csv}"

# Hosts del clúster (LAN)
ES_HOSTS=("10.20.90.21" "10.20.90.29" "10.20.90.28")
ES_SCHEME="${ES_SCHEME:-http}"
ES_PORT="${ES_PORT:-9200}"

# Auth (puedes exportar AUTH="elastic:xxxxx")
AUTH="${AUTH:-elastic:changeme}"

# Parámetros de benchmark (6 ejecuciones: (3,6) shards × (1,2,4) workers)
SHARDS_LIST=(${SHARDS_LIST:-3 6})
WORKERS_LIST=(${WORKERS_LIST:-1 2 4})

DOCS_PER_BULK="${DOCS_PER_BULK:-20000}"   # 20k docs/bulk
LINES_PER_CHUNK=$((DOCS_PER_BULK * 2))   # 2 líneas por doc (acción + doc)

USE_GZIP="${USE_GZIP:-1}"                 # 1 = enviar bulks gz

    xargs -0 -P "$workers" -n 1 bash -lc '

      suf="${f##*_}"          # 0000
      n=$((10#$suf))          # base10
      case $((n%3)) in

        1) host="$ES_HOST1";;
        2) host="$ES_HOST2";;

      else
        out=$(curl -sS -u "$AUTH" -H "Content-Type: application/x-ndjson" --data-binary @"$f" "$url")
      fi

      echo "$out" | grep -q "\"errors\":true" && echo "[!] Bulk chunk con errores: $f (host $host)" >&2
    ' _

  t1=$(date +%s%N)
  python3 - <<PY
t0=$t0; t1=$t1
print(round((t1-t0)/1e9, 2))
PY
}

    #!/usr/bin/env python3
"""bench_covid_bulk.py — Carga CSV a Elasticsearch con Bulk API y métricas básicas.

Uso:
  AUTH="elastic:changeme" ES="http://10.20.90.21:9200" \
  ./bench_covid_bulk.py --csv covid_raw.csv --index covid_raw_s3 --batch-docs 20000 --gzip

Opciones:
  --set-replicas-1  (pone replicas=1 antes de indexar; útil para comparar)
"""

import argparse
import csv
import gzip
import os
import sys
import time
from datetime import datetime
from typing import Dict, Iterator, List, Tuple
import requests

def iter_rows(csv_path: str) -> Iterator[Dict[str, str]]:
    with open(csv_path, newline='', encoding='utf-8') as f:
        r = csv.DictReader(f)
        for row in r:
            yield row

def to_doc(row: Dict[str, str]) -> Dict:
    return {
        "provincia_iso": row["provincia_iso"],
        "sexo": row["sexo"],
        "grupo_edad": row["grupo_edad"],
        "fecha": row["fecha"],
        "num_casos": int(row["num_casos"] or 0),
        "num_hosp": int(row["num_hosp"] or 0),
        "num_uci": int(row["num_uci"] or 0),
        "num_def": int(row["num_def"] or 0),
    }

def bulk_chunks(rows: Iterator[Dict[str,str]], index: str, batch_docs: int) -> Iterator[Tuple[int, bytes]]:
    buf: List[str] = []
    n = 0
    for row in rows:
        meta = {"index": {"_index": index}}
        buf.append(json_dumps(meta))
        buf.append(json_dumps(to_doc(row)))
        n += 1
        if n >= batch_docs:
            payload = "\n".join(buf) + "\n"
            yield n, payload.encode('utf-8')
            buf = []
            n = 0
    if n:
        payload = "\n".join(buf) + "\n"
        yield n, payload.encode('utf-8')

def json_dumps(obj) -> str:
    import json
    return json.dumps(obj, ensure_ascii=False, separators=(",", ":"))

def set_replicas(es: str, auth: str, index: str, replicas: int):
    r = requests.put(f"{es}/{index}/_settings", auth=tuple(auth.split(":",1)),
                     headers={"Content-Type":"application/json"},
                     data=f'{{"index":{{"number_of_replicas":{replicas}}}}}')
    r.raise_for_status()

def wait_green(es: str, auth: str, index: str, timeout_s: int = 900):
    r = requests.get(f"{es}/_cluster/health/{index}", auth=tuple(auth.split(":",1)),
                     params={"wait_for_status":"green","wait_for_no_relocating_shards":"true","timeout":f"{timeout_s}s"})
    r.raise_for_status()

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--csv", required=True)
    ap.add_argument("--index", required=True)
    ap.add_argument("--batch-docs", type=int, default=20000)
    ap.add_argument("--gzip", action="store_true")
    ap.add_argument("--set-replicas-1", action="store_true")
    args = ap.parse_args()

    es = os.environ.get("ES", "http://10.20.90.21:9200")
    auth = os.environ.get("AUTH", "elastic:changeme")

    if args.set_replicas_1:
        set_replicas(es, auth, args.index, 1)
        wait_green(es, auth, args.index)

    url = f"{es}/_bulk"
    headers = {"Content-Type": "application/x-ndjson"}
    if args.gzip:
        headers["Content-Encoding"] = "gzip"

    total_docs = 0
    t0 = time.time()
    last = t0
    sent_bytes = 0
    bulk_errors = 0

    for n_docs, payload in bulk_chunks(iter_rows(args.csv), args.index, args.batch_docs):
        if args.gzip:
            payload = gzip.compress(payload)
        sent_bytes += len(payload)
        r = requests.post(url, auth=tuple(auth.split(":",1)), headers=headers, data=payload)
        r.raise_for_status()
        j = r.json()
        if j.get("errors"):
            bulk_errors += 1

        total_docs += n_docs
        now = time.time()
        if now - last >= 1.0:
            rate = total_docs / (now - t0)
            mb_s = (sent_bytes / (now - t0)) / (1024*1024)
            print(f"{total_docs:,} docs | {rate:,.0f} docs/s | {mb_s:,.2f} MB/s | bulk_errors={bulk_errors}")
            last = now

    t1 = time.time()
    dt = t1 - t0
    rate = total_docs / dt
    mb_s = (sent_bytes / dt) / (1024*1024)

    print("\n=== RESULTADO INDEXACIÓN ===")
    print(f"Index: {args.index}")
    print(f"Docs:  {total_docs:,}")
    print(f"Time:  {dt:.2f} s")
    print(f"Rate:  {rate:,.0f} docs/s")
    print(f"Sent:  {sent_bytes/(1024*1024):.2f} MB (NDJSON/gzip)")
    print(f"Thpt:  {mb_s:.2f} MB/s")
    print(f"Bulk errors: {bulk_errors}")

if __name__ == "__main__":
    try:
        import requests  # noqa
    except ImportError:
        print("Falta requests: pip install requests", file=sys.stderr)
        sys.exit(2)
    main()

# Crea copias del índice covid_raw con distintos shards:

need() { command -v "$1" >/dev/null 2>&1 || { echo "Falta comando: $1"; exit 1; }; }

SOURCE_INDEX="${1:-covid_raw}"

REPLICAS="${REPLICAS:-1}"

echo "[i] ES:           $ES"
echo "[i] replicas:     $REPLICAS"
echo ""

mapping="$(curl -sS -u "$AUTH" "$ES/$SOURCE_INDEX/_mapping")"
settings="$(curl -sS -u "$AUTH" "$ES/$SOURCE_INDEX/_settings")"

# Extract just the properties part for the index name
# We'll use ES to accept the mapping as-is by sending the entire mapping for the new index.
# Simpler approach: create target index with dynamic mapping off and then reindex; but we want same mapping.
# We'll instead just rely on ES to infer mapping from reindex (works if source mapping exists).

for entry in $TARGETS; do
  target="${entry%%:*}"
  shards="${entry#*:}"

  props="$(curl -sS -u "$AUTH" "$ES/$SOURCE_INDEX/_mapping" | python3 - <<PY "$SOURCE_INDEX"
import json,sys
idx=sys.argv[1]
m=json.load(sys.stdin)
# handle possible aliases; pick first key if idx not exact
key = idx if idx in m else next(iter(m.keys()))
props = m[key]["mappings"]
print(json.dumps(props))
PY
)"

  curl -sS -u "$AUTH" -H 'Content-Type: application/json' -X PUT "$ES/$target" -d "{

      \"number_of_shards\": $shards,
      \"number_of_replicas\": $REPLICAS,
      \"refresh_interval\": \"1s\"

  if [[ "$FORCEMERGE" == "1" ]]; then
    echo "[+] Force-merge $target (max_num_segments=1)"
    curl -sS -u "$AUTH" -X POST "$ES/$target/_forcemerge?max_num_segments=1" >/dev/null
  fi

  cnt="$(curl -sS -u "$AUTH" "$ES/$target/_count" | python3 -c 'import sys,json; print(json.load(sys.stdin)["count"])')"

/**

const ES_URL = __ENV.ES_URL || "http://10.20.90.21:9200";
const ES_INDEX = __ENV.ES_INDEX || "covid_raw";
const AUTH_USER = __ENV.AUTH_USER || "elastic";

const REQUEST_CACHE = (__ENV.REQUEST_CACHE || "1") === "1";
const RANDOMIZE = (__ENV.RANDOMIZE || "0") === "1";
const THINK_TIME_MS = parseInt(__ENV.THINK_TIME_MS || "0", 10);

export const options = {
  vus: parseInt(__ENV.VUS || "10", 10),
  duration: __ENV.DURATION || "60s",
  // Optional cap; set RPS=0 to disable
  rps: parseInt(__ENV.RPS || "0", 10) || undefined,

    http_req_duration: ["p(95)<2000"],

};

const baseUrl = `${ES_URL.replace(/\/$/, "")}/${encodeURIComponent(ES_INDEX)}/_search`;

// Helper: random date window within [2020-01-01, 2022-12-31]
function randomDateWindow(daysWindow) {
  const startMin = new Date("2020-01-01T00:00:00Z").getTime();
  const startMax = new Date("2022-12-01T00:00:00Z").getTime(); // so +window doesn't exceed year
  const start = new Date(startMin + Math.random() * (startMax - startMin));
  const end = new Date(start.getTime() + daysWindow * 24 * 3600 * 1000);
  const fmt = (d) => d.toISOString().slice(0, 10);
  return { gte: fmt(start), lte: fmt(end) };
}

function postQuery(name, body) {
  const params = {
    headers: { "Content-Type": "application/json" },
    auth: "basic",
    user: AUTH_USER,
    pass: AUTH_PASS,
    tags: { q: name },
  };

  // request_cache only applies to search requests. Best for agg-only dashboards.
  const url = REQUEST_CACHE ? `${baseUrl}?request_cache=true` : `${baseUrl}?request_cache=false`;

  const res = http.post(url, JSON.stringify(body), params);
  check(res, { "status 200": (r) => r.status === 200 });
}

    },
    aggs: {
      por_edad: {
        terms: { field: "grupo_edad", size: 20, order: { casos: "desc" } },
        aggs: { casos: { sum: { field: "num_casos" } } },
      },
    },
  });
}

// Q5: Multi-metric per provincia for a window
function q_metrics_by_provincia() {
  const range = RANDOMIZE ? randomDateWindow(365) : { gte: "2020-01-01", lte: "2021-12-31" };
  postQuery("metrics_by_provincia", {
    size: 0,
    track_total_hits: false,
    query: { range: { fecha: range } },
    aggs: {
      prov: {
        terms: { field: "provincia_iso", size: 60, order: { casos: "desc" } },
        aggs: {
          casos: { sum: { field: "num_casos" } },
          hosp: { sum: { field: "num_hosp" } },
          uci: { sum: { field: "num_uci" } },
          def: { sum: { field: "num_def" } },
        },
      },
    },
  });
}

// Q6: "Detail view" - fetch recent docs for a provincia with sort
function q_detail_recent_docs() {
  const range = RANDOMIZE ? randomDateWindow(30) : { gte: "2021-01-01", lte: "2021-12-31" };
  postQuery("detail_recent_docs", {
    size: 50,
    track_total_hits: false,
    query: {
      bool: {
        filter: [
          { term: { provincia_iso: "A" } },
          { range: { fecha: range } },
        ],
      },
    },
    sort: [{ fecha: "desc" }],
    _source: ["provincia_iso", "sexo", "grupo_edad", "fecha", "num_casos", "num_hosp", "num_uci", "num_def"],
  });
}

// Weighted mix (rough dashboard distribution)
const QUERIES = [
  { fn: q_timeseries_cases_day, w: 3 },
  { fn: q_timeseries_deaths_week, w: 2 },
  { fn: q_top_provincias_cases, w: 2 },
  { fn: q_prov_sexo_by_age, w: 2 },
  { fn: q_metrics_by_provincia, w: 2 },
  { fn: q_detail_recent_docs, w: 1 },
];

const totalW = QUERIES.reduce((a, q) => a + q.w, 0);

function pickQuery() {
  let r = Math.random() * totalW;
  for (const q of QUERIES) {
    r -= q.w;
    if (r <= 0) return q.fn;
  }
  return QUERIES[QUERIES.length - 1].fn;
}

export default function () {
  const fn = pickQuery();
  fn();
  if (THINK_TIME_MS > 0) sleep(THINK_TIME_MS / 1000);
}

    G.3 Runner Bash (matriz coordinador × índice × workers): run_elastic_query_benchmarks.sh

    #!/usr/bin/env bash
set -euo pipefail

# ============================================================
# Runner: batería de benchmarks de CONSULTA (k6) para Elasticsearch
# Variación por:
#   - nodo coordinador (endpoint HTTP)
#   - índice (distintos shards -> distintos índices)
#   - "workers" (concurrencia) = VUs en k6
#
# Requisitos: bash, python3, k6, curl
#
# Uso:
#   AUTH="elastic:changeme" ./run_elastic_query_benchmarks.sh
#
# Variables opcionales:
#   COORDINATORS="10.20.90.21 10.20.90.29 10.20.90.28"
#   INDEXES="covid_raw_s3:3 covid_raw_s6:6"   # formato index:shards
#   WORKERS="1 2 4 8"                         # VUs en k6
#   DURATION="60s"
#   WARMUP="20s"                              # 0s para desactivar
#   RPS="0"                                   # 0 = sin límite
#   REQUEST_CACHE="1"                         # 0/1
#   RANDOMIZE="0"                             # 0/1 (si 1 reduce efecto de cache)
#   THINK_TIME_MS="0"
#   ES_SCHEME="http"
#   ES_PORT="9200"
# ============================================================

need() { command -v "$1" >/dev/null 2>&1 || { echo "Falta comando: $1"; exit 1; }; }
need bash
need python3
need curl
need k6

AUTH="${AUTH:-elastic:changeme}"
AUTH_USER="${AUTH%%:*}"
AUTH_PASS="${AUTH#*:}"

ES_SCHEME="${ES_SCHEME:-http}"
ES_PORT="${ES_PORT:-9200}"

COORDINATORS="${COORDINATORS:-10.20.90.21 10.20.90.29 10.20.90.28}"
INDEXES="${INDEXES:-covid_raw_s3:3 covid_raw_s6:6}"
WORKERS="${WORKERS:-1 2 4}"

DURATION="${DURATION:-60s}"
WARMUP="${WARMUP:-20s}"
RPS="${RPS:-0}"
REQUEST_CACHE="${REQUEST_CACHE:-1}"
RANDOMIZE="${RANDOMIZE:-0}"
THINK_TIME_MS="${THINK_TIME_MS:-0}"

K6_SCRIPT="${K6_SCRIPT:-k6_covid_queries.js}"

TS="$(date +%Y%m%d_%H%M%S)"
OUT_DIR="query_bench_${TS}"
SUM_DIR="${OUT_DIR}/summaries"
mkdir -p "$SUM_DIR"

OUT_CSV="${OUT_DIR}/query_benchmark_results.csv"
OUT_PERQ_CSV="${OUT_DIR}/query_benchmark_per_query.csv"

echo "timestamp,run_id,coordinator,index,shards,workers,vus,duration_s,rps,request_cache,randomize,http_reqs,rps_measured,fail_rate,p50_ms,p95_ms,p99_ms,avg_ms,max_ms" > "$OUT_CSV"
echo "timestamp,run_id,coordinator,index,shards,workers,query_tag,reqs,p50_ms,p95_ms,p99_ms,avg_ms" > "$OUT_PERQ_CSV"

to_seconds() {
  python3 - <<PY "$1"
import re,sys
s=sys.argv[1]
m=re.fullmatch(r"(\d+)(ms|s|m|h)", s.strip())
if not m:
  print(0); sys.exit(0)
n=int(m.group(1)); u=m.group(2)
mult={"ms":0.001,"s":1,"m":60,"h":3600}[u]
print(int(n*mult))
PY
}

DUR_S="$(to_seconds "$DURATION")"

# Sanity: reach coordinators
for host in $COORDINATORS; do
  url="${ES_SCHEME}://${host}:${ES_PORT}"
  curl -sS -u "$AUTH" --max-time 3 "$url" >/dev/null || {
    echo "[!] No puedo acceder a $url"; exit 1;
  }
done

parse_summary() {
  python3 - <<'PY' "$@"
import json, sys, datetime, re

summary_path, ts, run_id, coord, index, shards, workers, vus, duration_s, rps, request_cache, randomize, out_csv, out_perq = sys.argv[1:]

def g(metric_key):
  return data.get("metrics", {}).get(metric_key, {}).get("values", {})

with open(summary_path, "r", encoding="utf-8") as f:
  data=json.load(f)

# Overall
dur = g("http_req_duration")
reqs = g("http_reqs").get("count", 0)
fail = g("http_req_failed").get("rate", 0.0)

def pick(values, key, default=""):
  v = values.get(key, default)
  return v

p50 = pick(dur, "med", "")
p95 = pick(dur, "p(95)", "")
p99 = pick(dur, "p(99)", "")
avg = pick(dur, "avg", "")
mx  = pick(dur, "max", "")

rps_measured = (reqs / float(duration_s)) if float(duration_s) > 0 else 0.0

with open(out_csv, "a", encoding="utf-8") as out:
  out.write(",".join(map(str, [
    ts, run_id, coord, index, shards, workers, vus, duration_s, rps, request_cache, randomize,
    reqs, round(rps_measured, 2), round(float(fail), 6),
    round(float(p50), 3) if p50!="" else "", round(float(p95), 3) if p95!="" else "",
    round(float(p99), 3) if p99!="" else "", round(float(avg), 3) if avg!="" else "",
    round(float(mx), 3) if mx!="" else ""
  ])) + "\n")

# Per query submetrics (tag q)
metrics = data.get("metrics", {})
pattern = re.compile(r'^http_req_duration\{q:([^}]+)\}$')
for k in list(metrics.keys()):
  m = pattern.match(k)
  if not m:
    continue
  tag = m.group(1)
  v = metrics[k].get("values", {})
  # k6 doesn't always include count for trends; use http_reqs tag submetric if present
  # We'll try http_reqs{q:tag} for req count
  reqk = f"http_reqs{{q:{tag}}}"
  reqc = metrics.get(reqk, {}).get("values", {}).get("count", "")
  p50t = v.get("med", "")
  p95t = v.get("p(95)", "")
  p99t = v.get("p(99)", "")
  avgt = v.get("avg", "")
  with open(out_perq, "a", encoding="utf-8") as out:
    out.write(",".join(map(str, [
      ts, run_id, coord, index, shards, workers, tag, reqc,
      round(float(p50t), 3) if p50t!="" else "",
      round(float(p95t), 3) if p95t!="" else "",
      round(float(p99t), 3) if p99t!="" else "",
      round(float(avgt), 3) if avgt!="" else "",
    ])) + "\n")
PY
}

echo ""
echo "== Query benchmark suite =="
echo "Coordinators: $COORDINATORS"
echo "Indexes:      $INDEXES"
echo "Workers(VUs): $WORKERS"
echo "Duration:     $DURATION (warmup $WARMUP)"
echo "Cache:        REQUEST_CACHE=$REQUEST_CACHE, RANDOMIZE=$RANDOMIZE"
echo "Output dir:   $OUT_DIR"
echo ""

# Run matrix
for entry in $INDEXES; do
  index="${entry%%:*}"
  shards="${entry#*:}"

  for coord in $COORDINATORS; do
    es_url="${ES_SCHEME}://${coord}:${ES_PORT}"

    for w in $WORKERS; do
      run_id="idx=${index}_s=${shards}_coord=${coord}_w=${w}"
      sum_warm="${SUM_DIR}/${run_id}_warm.json"
      sum_real="${SUM_DIR}/${run_id}.json"
      ts="$(date -Iseconds)"

      echo "[RUN] $run_id"

      # Warm-up (discard)
      if [[ "$WARMUP" != "0s" && "$WARMUP" != "0" ]]; then
        k6 run "$K6_SCRIPT" \
          --quiet \
          --summary-trend-stats="avg,min,med,max,p(90),p(95),p(99)" \
          --summary-export="$sum_warm" \
          -e ES_URL="$es_url" -e ES_INDEX="$index" \
          -e AUTH_USER="$AUTH_USER" -e AUTH_PASS="$AUTH_PASS" \
          -e REQUEST_CACHE="$REQUEST_CACHE" -e RANDOMIZE="$RANDOMIZE" \
          -e THINK_TIME_MS="$THINK_TIME_MS" \
          -e VUS="$w" -e DURATION="$WARMUP" -e RPS="$RPS" >/dev/null
      fi

      # Measured run
      k6 run "$K6_SCRIPT" \
        --quiet \
        --summary-trend-stats="avg,min,med,max,p(90),p(95),p(99)" \
        --summary-export="$sum_real" \
        -e ES_URL="$es_url" -e ES_INDEX="$index" \
        -e AUTH_USER="$AUTH_USER" -e AUTH_PASS="$AUTH_PASS" \
        -e REQUEST_CACHE="$REQUEST_CACHE" -e RANDOMIZE="$RANDOMIZE" \
        -e THINK_TIME_MS="$THINK_TIME_MS" \
        -e VUS="$w" -e DURATION="$DURATION" -e RPS="$RPS" >/dev/null

      parse_summary "$sum_real" "$ts" "$run_id" "$coord" "$index" "$shards" "$w" "$w" "$DUR_S" "$RPS" "$REQUEST_CACHE" "$RANDOMIZE" "$OUT_CSV" "$OUT_PERQ_CSV"

      echo "  -> ok (summary: $sum_real)"
    done
  done
done

echo ""
echo "[OK] Terminado."
echo "Resumen por ejecución: $OUT_CSV"
echo "Resumen por query:     $OUT_PERQ_CSV"
echo "Carpeta:              $OUT_DIR"
