    Laboratorio 1: extracción de PostgreSQL y conversión a JSON

    Objetivos

    En este laboratorio se construirá un flujo ETL sencillo para extraer información desde PostgreSQL, convertir el resultado a formato JSON y almacenarlo en un fichero.

    Al finalizar serás capaz de:

    • Configurar una conexión JDBC mediante DBCPConnectionPool.
    • Extraer registros de PostgreSQL.
    • Convertir los resultados SQL a formato JSON.
    • Guardar el resultado mediante PutFile.
    • Comprobar el contenido generado.
    • Identificar los errores más habituales.

    1. Escenario

    Una empresa dispone de una tabla PostgreSQL denominada clientes. Se necesita extraer periódicamente su contenido y generar un fichero JSON que pueda ser consumido por otro sistema.

    La tabla contiene la siguiente información:

    Campo Descripción
    id Identificador del cliente
    nombre Nombre del cliente
    email Correo electrónico
    ciudad Ciudad de residencia

    El resultado se almacenará en:

    /datos/salida/clientes.json

    T --> L

    flowchart LR

    3. Componentes utilizados

    Componente Función
    GenerateFlowFile Activa la ejecución del flujo
    ExecuteSQLRecord Ejecuta la consulta SQL
    DBCPConnectionPool Proporciona la conexión JDBC
    JsonRecordSetWriter Convierte las filas SQL a JSON

    GenerateFlowFile únicamente actúa como disparador. Su contenido no se utilizará durante la consulta.

    Laboratorio: Ingesta de datos meteorológicos desde Open-Meteo hacia MongoDB

    Objetivos

    En este laboratorio construiremos un flujo ETL completo utilizando Apache NiFi 2.10, capaz de consultar una API REST pública, transformar la información recibida y almacenarla en una base de datos NoSQL.

    El objetivo es reproducir un escenario muy habitual en proyectos de IoT, Smart Cities, Big Data y Data Engineering, donde miles de dispositivos generan información que debe ser capturada, procesada y almacenada para su posterior análisis.

    Durante el laboratorio se utilizará la API pública de Open-Meteo, que proporciona información meteorológica en tiempo real sin necesidad de registrarse ni obtener una API Key.

    Al finalizar el laboratorio serás capaz de:

    • Consumir una API REST mediante InvokeHTTP.
    • Procesar respuestas JSON.
    • Transformar datos utilizando Processors especializados.
    • Configurar un MongoDBControllerService.
    • Almacenar documentos JSON en MongoDB.
    • Analizar el recorrido de los FlowFiles mediante Data Provenance.
    • Comprender cómo implementar un proceso ETL completo con Apache NiFi.

    Escenario

    Una empresa dedicada al análisis de datos meteorológicos desea almacenar automáticamente la temperatura y otras variables climáticas de distintas ciudades para realizar estudios históricos y generar cuadros de mando.

    Para ello utilizará Apache NiFi como plataforma de integración de datos.

    Cada minuto, NiFi realizará las siguientes operaciones:

    1. Consultará la API de Open-Meteo.
    2. Obtendrá las condiciones meteorológicas actuales de la ciudad de Xàtiva.
    3. Transformará la respuesta para conservar únicamente la información relevante.
    4. Añadirá la fecha y hora en la que NiFi realizó la captura.
    5. Almacenará el resultado como un documento independiente en MongoDB.

    El proceso puede repetirse periódicamente, permitiendo construir un histórico de mediciones que posteriormente podrá analizarse mediante herramientas de Business Intelligence o plataformas Big Data.

    Arquitectura ETL

    El laboratorio implementará las tres fases clásicas de cualquier proceso ETL:

    flowchart LR
    E["Extract"]
    T["Transform"]
    L["Load"]

    E --> T --> L

    Cada una de ellas tendrá un objetivo concreto:

    Fase Descripción
    Extract Consulta la API REST de Open-Meteo y obtiene los datos meteorológicos en formato JSON.
    Transform Selecciona únicamente los campos necesarios, reorganiza el documento y añade información adicional generada por NiFi.
    Load Inserta el documento final en una colección MongoDB para su almacenamiento histórico.

    Arquitectura del flujo en Apache NiFi

    La implementación del proceso ETL se realizará mediante el siguiente flujo:

    flowchart LR

A["GenerateFlowFile"]
B["InvokeHTTP"]
C["JoltTransformJSON"]
D["UpdateRecord"]
E["PutMongoRecord"]
F["LogAttribute"]

A --> B
B --> C
C --> D
D --> E
E --> F

    Cada Processor desempeña una función específica dentro del flujo:

    Processor Función
    GenerateFlowFile Activa periódicamente el flujo.
    InvokeHTTP Consulta la API REST de Open-Meteo.
    JoltTransformJSON Simplifica y reorganiza la respuesta JSON.
    UpdateRecord Añade información adicional al documento.
    PutMongoRecord Inserta el documento en MongoDB.
    LogAttribute Permite verificar la correcta ejecución del flujo.

    Los Processors compartirán varios Controller Services, evitando duplicar configuraciones y siguiendo las buenas prácticas estudiadas en capítulos anteriores.

    Documento que se almacenará

    Cada ejecución del flujo generará un documento similar al siguiente:

    {
    "city": "Xàtiva",
    "latitude": 38.9878,
    "longitude": -0.5186,
    "temperature": 29.4,
    "humidity": 63,
    "wind_speed": 11.8,
    "precipitation": 0,
    "cloud_cover": 18,
    "timestamp_api": "2026-08-05T18:30",
    "timestamp_nifi": "2026-08-05T18:30:42"
}

    Obsérvese la diferencia entre ambos campos temporales:

    • timestamp_api indica cuándo el proveedor meteorológico realizó la medición.
    • timestamp_nifi registra el instante exacto en que Apache NiFi procesó dicha información.

    Esta diferencia resulta muy útil para medir retrasos de procesamiento, detectar incidencias y auditar la calidad de los datos.
