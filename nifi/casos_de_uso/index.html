    Laboratorio 1: extraccion de PostgreSQL y conversion a JSON

    Objetivos

    En este laboratorio se construira un flujo ETL sencillo para extraer informacion desde PostgreSQL, convertir el resultado a formato JSON y almacenarlo en un fichero.

    Al finalizar seras capaz de:

    • Configurar una conexion JDBC mediante DBCPConnectionPool.
    • Extraer registros de PostgreSQL con ExecuteSQLRecord.
    • Convertir filas SQL a JSON con JsonRecordSetWriter.
    • Definir atributos con UpdateAttribute.
    • Guardar el resultado con PutFile.

    Escenario

    Una empresa dispone de una tabla PostgreSQL denominada clientes. Se necesita exportar periodicamente su contenido a un fichero JSON.

    Tabla de ejemplo:

    CREATE TABLE clientes (
    id SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL,
    ciudad VARCHAR(100)
);

    Datos de prueba:

    INSERT INTO clientes (nombre, email, ciudad)
VALUES
    ('Ana Lopez', 'ana@empresa.com', 'Valencia'),
    ('Carlos Ruiz', 'carlos@empresa.com', 'Madrid'),
    ('Laura Perez', 'laura@empresa.com', 'Sevilla');

    Arquitectura ETL

    flowchart LR
    E["Extract<br/>PostgreSQL"]
    T["Transform<br/>Records a JSON"]
    L["Load<br/>Fichero JSON"]

    E --> T
    T --> L

    Flujo en NiFi:

    flowchart LR
    G["GenerateFlowFile"] --> SQL["ExecuteSQLRecord"]
    SQL --> U["UpdateAttribute"]
    U --> F["PutFile"]

    SQL -.-> DBCP["DBCPConnectionPool"]
    SQL -.-> WRITER["JsonRecordSetWriter"]

    Preparacion del entorno

    Directorio de salida (host):

    mkdir -p /opt/nifi/datos/salida
chmod -R 777 /opt/nifi/datos

    Si NiFi se ejecuta en Docker, montar volumen:

    volumes:
  - /opt/nifi/datos:/datos

    Controller Services

    DBCPConnectionPool (nombre sugerido: DBCP-POSTGRESQL-CLIENTES):

    Propiedad Valor
    Database Connection URL jdbc:postgresql://postgres:5432/clientes_db
    Database Driver Class Name org.postgresql.Driver
    Database Driver Location(s) /opt/nifi/drivers/postgresql.jar
    Database User nifi
    Password nifi123
    Validation Query SELECT 1

    JsonRecordSetWriter (nombre sugerido: JSON-WRITER-CLIENTES):

    Propiedad Valor
    Schema Write Strategy Do Not Write Schema
    Pretty Print JSON true

    Configuracion de Processors

    GenerateFlowFile:

    Propiedad Valor
    Run Schedule 1 hour
    Batch Size 1
    Custom Text exportar_clientes

    ExecuteSQLRecord:

    Propiedad Valor
    Database Connection Pooling Service DBCP-POSTGRESQL-CLIENTES
    Record Writer JSON-WRITER-CLIENTES
    SQL select query Consulta SQL

    Consulta SQL:

    SELECT
    id,
    nombre,
    email,
    ciudad
FROM clientes
ORDER BY id;

    UpdateAttribute:

    filename = clientes.json

    PutFile:

    Propiedad Valor
    Directory /datos/salida
    Conflict Resolution Strategy replace
    Create Missing Directories true

    Secuencia de ejecucion

    sequenceDiagram
    participant G as GenerateFlowFile
    participant S as ExecuteSQLRecord
    participant D as DBCPConnectionPool
    participant W as JsonRecordSetWriter
    participant P as PutFile

    G->>S: Disparo del flujo
    S->>D: Solicitar conexion JDBC
    D-->>S: Conexion
    S->>W: Convertir filas a JSON
    W-->>S: Payload JSON
    S->>P: FlowFile transformado

    Validacion

    Comprobar fichero generado:

    cat /opt/nifi/datos/salida/clientes.json

    Resultado esperado (ejemplo):

    [
  {
    "id": 1,
    "nombre": "Ana Lopez",
    "email": "ana@empresa.com",
    "ciudad": "Valencia"
  },
  {
    "id": 2,
    "nombre": "Carlos Ruiz",
    "email": "carlos@empresa.com",
    "ciudad": "Madrid"
  },
  {
    "id": 3,
    "nombre": "Laura Perez",
    "email": "laura@empresa.com",
    "ciudad": "Sevilla"
  }
]

    Errores frecuentes

    • ClassNotFoundException: org.postgresql.Driver: revisar ruta del driver.
    • Connection refused: comprobar contenedor/servicio PostgreSQL y puerto.
    • UnknownHostException: revisar red Docker y nombre de host.
    • Permission denied en PutFile: revisar permisos en /opt/nifi/datos.

    Resumen

    GenerateFlowFile -> ExecuteSQLRecord -> UpdateAttribute -> PutFile

    Este patron se puede reutilizar para exportaciones periodicas y ficheros de intercambio.

    Laboratorio: Ingesta de datos meteorologicos desde Open-Meteo hacia MongoDB

    Objetivos

    En este laboratorio construiremos un flujo ETL completo con Apache NiFi 2.10 para consultar Open-Meteo, transformar la respuesta y almacenar cada lectura en MongoDB.

    Al finalizar seras capaz de:

    • Consumir una API REST mediante InvokeHTTP.
    • Transformar JSON con JoltTransformJSON.
    • Enriquecer Records con UpdateRecord.
    • Conectar MongoDB con MongoDBControllerService.
    • Insertar documentos con PutMongoRecord.
    • Validar el recorrido con Data Provenance.

    Escenario

    Cada minuto, NiFi realizara las siguientes operaciones:

    1. Consultar Open-Meteo para Xativa.
    2. Extraer variables meteorologicas actuales.
    3. Reorganizar el JSON y dejar solo campos utiles.
    4. Anadir timestamp_nifi.
    5. Insertar un documento por lectura en MongoDB.

    Arquitectura ETL

    flowchart LR
    EX["Extract<br/>API Open-Meteo"]
    TR["Transform<br/>Jolt + UpdateRecord"]
    LO["Load<br/>MongoDB"]

    EX --> TR --> LO

    Flujo en NiFi:

    flowchart LR
    G["GenerateFlowFile"] --> H["InvokeHTTP"]
    H --> J["JoltTransformJSON"]
    J --> U["UpdateRecord"]
    U --> P["PutMongoRecord"]
    P --> L["LogAttribute"]

    P -.-> MONGO["MongoDBControllerService"]
    P -.-> READER["JsonTreeReader"]

    API Open-Meteo

    Coordenadas de Xativa:

    • Latitud: 38.9878
    • Longitud: -0.5186

    Endpoint:

    https://api.open-meteo.com/v1/forecast?latitude=38.9878&longitude=-0.5186&current=temperature_2m,relative_humidity_2m,wind_speed_10m,precipitation,cloud_cover&timezone=Europe%2FMadrid

    Respuesta de referencia:

    {
  "latitude": 38.99,
  "longitude": -0.52,
  "current": {
    "time": "2026-08-05T18:45",
    "temperature_2m": 31.4,
    "relative_humidity_2m": 42,
    "wind_speed_10m": 10.2,
    "precipitation": 0,
    "cloud_cover": 12
  }
}

    Preparacion de entorno

    docker-compose.yml (MongoDB):

    services:
  mongodb:
    image: mongo:8
    container_name: mongodb
    restart: unless-stopped
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db

volumes:
  mongo_data:

    Levantar servicio:

    docker compose up -d

    Comprobar estado:

    docker ps

    Controller Services (NiFi 2.10)

    MongoDBControllerService (nombre sugerido: MONGODB-WEATHER):

    Propiedad Valor
    Mongo URI mongodb://host.docker.internal:27017

    JsonTreeReader (nombre sugerido: JSON-READER):

    Propiedad Valor
    Schema Access Strategy Infer Schema

    Configuracion de Processors

    GenerateFlowFile:

    Propiedad Valor
    Run Schedule 60 sec
    Batch Size 1

    InvokeHTTP:

    Propiedad Valor
    HTTP Method GET
    HTTP URL Endpoint completo de Open-Meteo

    JoltTransformJSON:

    Especificacion recomendada:

    [
  {
    "operation": "shift",
    "spec": {
      "latitude": "latitude",
      "longitude": "longitude",
      "current": {
        "time": "timestamp_api",
        "temperature_2m": "temperature",
        "relative_humidity_2m": "humidity",
        "wind_speed_10m": "wind_speed",
        "precipitation": "precipitation",
        "cloud_cover": "cloud_cover"
      }
    }
  },
  {
    "operation": "default",
    "spec": {
      "city": "Xativa"
    }
  }
]

    UpdateRecord:

    • Anadir campo timestamp_nifi con expresion:
    ${now():format("yyyy-MM-dd'T'HH:mm:ss")}

    PutMongoRecord:

    Propiedad Valor
    Client Service MONGODB-WEATHER
    Mongo Database Name weather
    Mongo Collection Name current_weather
    Record Reader JSON-READER
    Batch Size 1

    Documento final esperado

    {
  "city": "Xativa",
  "latitude": 38.9878,
  "longitude": -0.5186,
  "temperature": 31.4,
  "humidity": 42,
  "wind_speed": 10.2,
  "precipitation": 0,
  "cloud_cover": 12,
  "timestamp_api": "2026-08-05T18:45",
  "timestamp_nifi": "2026-08-05T18:45:30"
}

    Verificacion en MongoDB

    Entrar a Mongo shell:

    docker exec -it mongodb mongosh

    Consultar datos:

    use weather
db.current_weather.find().pretty()

    Errores frecuentes

    • MongoDBControllerService deshabilitado: habilitar servicio y comprobar URI.
    • Error de conexion: validar host/puerto y red Docker.
    • Record Reader no asignado en PutMongoRecord.
    • Error de transformacion Jolt por nombres de campo incorrectos.

    Data Provenance

    Comprobar eventos principales:

    flowchart LR
    C["CREATE"] --> F["FETCH"]
    F --> M["CONTENT_MODIFIED"]
    M --> S["SEND"]

    Esto permite validar el linaje completo de cada FlowFile.

    Resumen

    GenerateFlowFile -> InvokeHTTP -> JoltTransformJSON -> UpdateRecord -> PutMongoRecord -> LogAttribute

    Este patron es reutilizable para otras APIs IoT, sensores y fuentes JSON en tiempo real.
