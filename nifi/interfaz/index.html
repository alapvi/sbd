    Capítulo 3. La interfaz gráfica de Apache NiFi 2.x

    Objetivo del capítulo: conocer el entorno de trabajo de Apache NiFi y aprender a organizar flujos de forma profesional antes de construir el primer pipeline.

    Objetivos de aprendizaje

    Al finalizar este capítulo serás capaz de:

    • Identificar todas las zonas de la interfaz.
    • Comprender la función de cada componente gráfico.
    • Navegar por el Canvas.
    • Organizar flujos mediante Process Groups.
    • Aplicar buenas prácticas de diseño.

    3.1 El Canvas

    Cuando Apache NiFi se inicia, el usuario accede al Canvas, el espacio de trabajo donde se diseñan y administran los flujos de datos.

    flowchart LR
    A[Processor de entrada] --> B[Processor de transformación]
    B --> C[Processor de salida]

    Características

    • Espacio de trabajo ampliable.
    • Zoom y desplazamiento.
    • Edición visual.
    • Modificación de flujos durante su ejecución.
    • Organización mediante Process Groups.

    Nota

    El Canvas representa visualmente el flujo, pero quien ejecuta el procesamiento es el motor interno de Apache NiFi.

    3.2 Anatomía de la interfaz

    Figura 3.1: Captura de pantalla de Apache NiFi 2.x (pendiente de insertar).

    Zona Función
    Toolbar Añadir componentes
    Canvas Diseñar flujos
    Navigation Navegar por el lienzo
    Search Buscar componentes
    Status Bar Consultar el estado del sistema

    3.3 La barra de componentes

    Componente Descripción
    Processor Ejecuta operaciones sobre FlowFiles
    Input Port Define un punto de entrada
    Output Port Define un punto de salida
    Process Group Organiza y encapsula partes del flujo
    Remote Process Group Permite comunicarse con otra instancia de NiFi
    Connection Une componentes y mantiene una cola de FlowFiles
    Funnel Concentra varias conexiones
    Label Añade documentación visual

    3.4 Navegación por el Canvas

    NiFi permite:

    • ampliar o reducir el zoom;
    • desplazarse por el lienzo;
    • seleccionar varios componentes;
    • mover y organizar elementos;
    • acceder a distintos niveles de Process Groups.

    Buena práctica

    Diseña los flujos de izquierda a derecha para facilitar su lectura.

    3.5 Estados de los componentes

    Estado Significado
    Running El componente está ejecutándose
    Stopped El componente está detenido
    Invalid La configuración está incompleta o contiene errores
    Disabled El componente está deshabilitado

    3.6 Configuración de un componente

    La mayoría de los Processors incluyen las siguientes pestañas:

    • Settings
    • Scheduling
    • Properties
    • Relationships
    • Comments

    Estas secciones permiten definir el comportamiento, la planificación, las propiedades y las rutas de salida de cada Processor.

    3.7 Process Groups

    Los Process Groups permiten dividir un flujo complejo en módulos más sencillos y reutilizables.

    flowchart LR
    A[Entrada de datos] --> B[Validación y transformación]
    B --> C[Salida de datos]

    Error frecuente

    Evita colocar todos los Processors en el Process Group raíz. Cuando el flujo crece, resulta difícil de comprender y mantener.

    3.8 Labels y documentación

    Los Labels permiten añadir explicaciones directamente sobre el Canvas.

    Se recomienda utilizarlos para:

    • describir la finalidad de cada bloque;
    • indicar el origen y destino de los datos;
    • señalar decisiones importantes;
    • documentar dependencias o requisitos.

    3.9 Buenas prácticas de diseño

    • Diseñar de izquierda a derecha.
    • Evitar conexiones cruzadas.
    • Utilizar nombres descriptivos.
    • Agrupar los componentes por funcionalidad.
    • Documentar los bloques mediante Labels.
    • Mantener una separación clara entre entrada, procesamiento y salida.
    • Preparar los flujos para utilizar Parameter Contexts.

    Ejemplo de organización:

    flowchart LR
    subgraph PG1[Entrada]
        A[GetFile]
    end

    subgraph PG2[Procesamiento]
        B[ConvertRecord]
        C[UpdateAttribute]
    end

    subgraph PG3[Salida]
        D[PutFile]
    end

    A --> B
    B --> C
    C --> D

    3.10 Errores frecuentes

    • Utilizar un Canvas desordenado.
    • Mantener los nombres predeterminados de los Processors.
    • Crear conexiones cruzadas.
    • No documentar el flujo.
    • Colocar todo el pipeline en un único Process Group.
    • Mezclar entrada, transformación y salida sin una organización visual.

    Laboratorio guiado 1. Primer contacto con el Canvas

    Objetivo

    Familiarizarse con la interfaz sin ejecutar todavía ningún flujo.

    Actividades

    1. Añade un Processor al Canvas.
    2. Selecciona GenerateFlowFile.
    3. Cambia su nombre por Generador de datos de prueba.
    4. Muévelo a otra zona del Canvas.
    5. Abre su ventana de configuración.
    6. Revisa las pestañas disponibles.
    7. Elimina el Processor.

    Laboratorio guiado 2. Diseño del primer flujo

    Construye el siguiente diseño sin ejecutarlo:

    flowchart LR
    A[GenerateFlowFile] -->|success| B[LogAttribute]

    Comprueba cómo:

    • crear los Processors;
    • establecer una Connection;
    • seleccionar la relación success;
    • mover los componentes;
    • añadir un Label;
    • mantener una disposición de izquierda a derecha.

    Resumen

    En este capítulo hemos aprendido:

    • qué es el Canvas;
    • cómo navegar por la interfaz;
    • qué componentes contiene la Toolbar;
    • cómo reconocer los estados de ejecución;
    • cómo organizar flujos mediante Process Groups;
    • qué buenas prácticas mejoran la mantenibilidad de un pipeline.
