    Capítulo 5. Primer flujo de datos con Apache NiFi 2.x

    Objetivo del capítulo: construir, ejecutar y observar el primer flujo de datos en Apache NiFi, comprendiendo cómo se crea un FlowFile, cómo circula por una conexión y cómo se inspeccionan sus atributos y su contenido.

    Objetivos de aprendizaje

    Al finalizar este capítulo serás capaz de:

    • Crear y configurar Processors.
    • Conectar componentes mediante Relationships.
    • Comprender el funcionamiento básico de una Queue.
    • Iniciar y detener un flujo.
    • Inspeccionar los atributos de un FlowFile.
    • Consultar el contenido de un FlowFile.
    • Utilizar Data Provenance para seguir su recorrido.
    • Interpretar los avisos y errores de configuración más habituales.

    5.1 El flujo que construiremos

    En este primer laboratorio utilizaremos dos Processors incluidos en Apache NiFi:

    • GenerateFlowFile
    • LogAttribute

    El flujo tendrá la siguiente estructura:

    flowchart LR
    A[GenerateFlowFile] -->|success| B[LogAttribute]

    GenerateFlowFile creará FlowFiles de prueba y LogAttribute escribirá sus atributos en el registro de NiFi.

    Finalidad del ejemplo

    Este flujo no pretende resolver todavía un caso real. Su objetivo es presentar el ciclo básico de creación, transferencia, almacenamiento temporal, ejecución y observación de un FlowFile.

    5.2 ¿Qué hace GenerateFlowFile?

    GenerateFlowFile es un Processor de origen. Puede crear FlowFiles con contenido aleatorio o con un contenido definido manualmente.

    No necesita recibir un FlowFile desde otro Processor, por lo que puede situarse al principio de un flujo.

    Entre sus usos habituales se encuentran:

    • realizar pruebas;
    • simular una fuente de datos;
    • generar mensajes periódicos;
    • comprobar el funcionamiento de una conexión;
    • realizar pruebas de carga.
    flowchart LR
    A[GenerateFlowFile] --> B[FlowFile nuevo]

    Processor de origen

    Un Processor de origen genera o recupera datos sin necesitar un FlowFile de entrada.

    Propiedades básicas

    Propiedad Función
    Custom Text Define el contenido que tendrá el FlowFile
    File Size Establece el tamaño del contenido generado
    Batch Size Indica cuántos FlowFiles se crean en cada ejecución
    Data Format Permite elegir entre texto personalizado y datos binarios
    Unique FlowFiles Determina si cada FlowFile debe contener datos diferentes

    En este laboratorio utilizaremos un texto JSON sencillo.

    {
  "mensaje": "Hola desde Apache NiFi",
  "origen": "GenerateFlowFile"
}

    5.3 ¿Qué hace LogAttribute?

    LogAttribute recibe un FlowFile y escribe sus atributos en el registro de NiFi.

    Puede utilizarse para:

    • comprobar qué atributos contiene un FlowFile;
    • depurar un flujo;
    • verificar cambios realizados por otros Processors;
    • examinar propiedades internas;
    • registrar temporalmente información durante el desarrollo.
    flowchart LR
    A[FlowFile] --> B[LogAttribute]
    B --> C[Registro de NiFi]

    Uso en producción

    LogAttribute es muy útil durante el aprendizaje y la depuración, pero registrar todos los atributos o el contenido de cada FlowFile puede generar un volumen elevado de logs. En producción debe utilizarse de forma controlada.

    Propiedades relevantes

    Propiedad Función
    Log Level Nivel utilizado para escribir en el registro
    Attributes to Log Lista de atributos que se mostrarán
    Log Payload Permite registrar también el contenido
    Log Prefix Añade un prefijo para identificar la salida
    Output Format Define el formato de presentación

    5.4 Crear el Process Group del laboratorio

    Antes de añadir los Processors, crea un Process Group que permita aislar este ejercicio.

    1. Arrastra un componente Process Group al Canvas.
    2. Asigna el nombre LAB 01 - Primer FlowFile.
    3. Abre el Process Group haciendo doble clic.
    4. Comprueba que el breadcrumb muestra la nueva ubicación.
    flowchart TB
    A[Root Process Group] --> B[LAB 01 - Primer FlowFile]

    Buena práctica

    Utiliza un Process Group independiente para cada laboratorio. Esto permite iniciar, detener, exportar o eliminar cada práctica sin afectar al resto del entorno.

    5.5 Añadir GenerateFlowFile

    1. Arrastra el icono Processor al Canvas.
    2. Escribe GenerateFlowFile en el buscador.
    3. Selecciona el Processor.
    4. Pulsa Add.

    Cambiar el nombre

    Cambia su nombre a:

    Generar mensaje JSON

    Configurar el contenido

    En Properties, configura Custom Text con:

    {
  "mensaje": "Hola desde Apache NiFi",
  "curso": "Sistemas Big Data",
  "capitulo": 5
}

    Configura además:

    Propiedad Valor
    Data Format Text
    Batch Size 1
    Unique FlowFiles false

    Contenido y atributos

    El JSON anterior formará parte del contenido del FlowFile. No se convertirá automáticamente en atributos.

    5.6 Configurar la planificación

    En Scheduling, establece:

    Propiedad Valor recomendado
    Scheduling Strategy Timer driven
    Run Schedule 10 sec
    Concurrent Tasks 1

    Con esta configuración se creará un FlowFile cada diez segundos.

    Evita una generación excesiva

    No configures inicialmente un intervalo de 0 sec. El Processor podría generar FlowFiles continuamente y llenar rápidamente la cola o el almacenamiento.

    5.7 Añadir LogAttribute

    1. Añade un segundo Processor.
    2. Busca LogAttribute.
    3. Selecciónalo.
    4. Cámbiale el nombre a Registrar atributos.

    Configuración recomendada

    Propiedad Valor
    Log Level info
    Log FlowFile Properties true
    Log Payload true
    Log Prefix LAB01
    Output Format Line per Attribute

    Datos sensibles

    Nunca actives Log Payload en un flujo real si el contenido puede incluir contraseñas, tokens, información personal u otros datos sensibles.

    5.8 Crear la Connection

    1. Sitúa el cursor sobre Generar mensaje JSON.
    2. Arrastra el manejador de conexión hasta Registrar atributos.
    3. Selecciona la Relationship success.
    4. Pulsa Add.
    flowchart LR
    A[Generar mensaje JSON] -->|success| B[Registrar atributos]

    La línea representa una Connection que contiene una cola:

    flowchart LR
    A[Processor A] --> Q[(Queue)]
    Q --> B[Processor B]

    Los FlowFiles permanecerán en esa cola hasta que el Processor de destino pueda procesarlos.

    5.9 Configurar las Relationships

    Cada Processor puede producir uno o varios resultados llamados Relationships.

    En este flujo:

    • GenerateFlowFile utiliza success.
    • LogAttribute también produce success.

    Como LogAttribute es el último Processor, su relación success debe terminarse automáticamente.

    1. Abre Registrar atributos.
    2. Accede a Relationships.
    3. Marca success como Automatically terminate.
    4. Guarda la configuración.
    flowchart LR
    A[GenerateFlowFile] -->|success| B[LogAttribute]
    B -->|success| C((Fin))

    Relación auto-terminada

    Una relación auto-terminada indica que los FlowFiles que lleguen a ella abandonarán el flujo y no necesitarán una Connection adicional.

    Processor no válido

    Si una Relationship no está conectada ni auto-terminada, NiFi considera que el Processor está incompletamente configurado.

    5.10 Validar el flujo

    Antes de iniciar los componentes, comprueba que:

    • ambos Processors tienen un nombre descriptivo;
    • GenerateFlowFile tiene configurado el contenido;
    • existe una Connection mediante success;
    • LogAttribute tiene auto-terminada su relación success;
    • no aparecen iconos de configuración inválida.
    Estado Interpretación
    Stopped Configurado, pero detenido
    Running Ejecutándose
    Invalid Configuración incompleta
    Disabled Deshabilitado
    Warning Existe algún aviso o bulletin

    Comprobar errores

    Sitúa el cursor sobre el icono de validación del Processor para consultar qué configuración falta.

    5.11 Iniciar el flujo

    Puedes iniciar los Processors individualmente o iniciar el Process Group completo.

    sequenceDiagram
    participant G as GenerateFlowFile
    participant Q as Queue
    participant L as LogAttribute

    G->>Q: Crea y transfiere un FlowFile
    Q->>L: Entrega el FlowFile
    L->>L: Registra atributos y contenido

    Tras unos segundos deberían aparecer estadísticas de entrada y salida sobre los componentes y las conexiones.

    5.12 Observar la Queue

    Detén temporalmente Registrar atributos y mantén activo Generar mensaje JSON.

    flowchart LR
    A[GenerateFlowFile activo] --> Q[(Queue con FlowFiles)]
    Q -. Processor detenido .-> B[LogAttribute]

    En la Connection podrás observar:

    • número de FlowFiles;
    • tamaño total;
    • datos de entrada y salida;
    • presión de retorno, si se alcanzan los límites.

    Después vuelve a iniciar Registrar atributos y comprueba cómo se vacía la cola.

    Qué demuestra esta prueba

    La Queue desacopla ambos Processors. El Processor de origen puede seguir produciendo datos aunque el Processor de destino esté detenido, mientras no se alcance el límite de back pressure.

    5.13 Listar los FlowFiles de una Queue

    1. Detén Registrar atributos.
    2. Espera a que se generen varios FlowFiles.
    3. Abre el menú contextual de la Connection.
    4. Selecciona List queue.

    La ventana mostrará información como:

    • UUID;
    • nombre del archivo;
    • tamaño;
    • fecha de entrada;
    • posición en la cola;
    • tiempo de permanencia.

    Selecciona un FlowFile para examinar sus atributos y su contenido.

    5.14 Atributos generados automáticamente

    NiFi añade varios atributos básicos:

    Atributo Descripción
    uuid Identificador único del FlowFile
    filename Nombre lógico del FlowFile
    path Ruta lógica asociada
    absolute.path Ruta absoluta lógica
    fileSize Tamaño del contenido
    entryDate Momento de entrada en la cola
    lineageStartDate Inicio del linaje

    UUID

    El UUID permite diferenciar cada FlowFile y seguir su recorrido mediante Data Provenance.

    5.15 Consultar el registro de LogAttribute

    Si NiFi se ejecuta mediante Docker Compose:

    docker compose logs -f nifi

    Para filtrar el prefijo configurado:

    docker compose logs nifi | grep LAB01

    La salida incluirá valores similares a:

    LAB01
uuid = 3f26c33a-...
filename = 7cbef2bb-...
fileSize = 92

{
  "mensaje": "Hola desde Apache NiFi",
  "curso": "Sistemas Big Data",
  "capitulo": 5
}

    Los valores serán diferentes

    El UUID y el nombre generado cambiarán en cada FlowFile.

    5.16 Consultar Data Provenance

    1. Abre el menú principal.
    2. Accede a Data Provenance.
    3. Filtra por Processor, UUID o intervalo temporal.
    4. Abre uno de los eventos.

    Podrás encontrar eventos como:

    • CREATE
    • ROUTE
    • CONTENT_MODIFIED
    • ATTRIBUTES_MODIFIED
    • DROP
    flowchart LR
    A[CREATE] --> B[ROUTE]
    B --> C[Procesamiento]
    C --> D[DROP o finalización]

    Data Provenance puede mostrar:

    • Processor que generó el evento;
    • UUID del FlowFile;
    • atributos anteriores y posteriores;
    • tamaño;
    • duración;
    • conexión de origen;
    • contenido asociado, si continúa disponible.

    Trazabilidad

    Data Provenance es una de las funcionalidades más importantes de NiFi para auditoría, depuración y análisis de incidencias.

    5.17 Detener el flujo correctamente

    1. Detén Generar mensaje JSON.
    2. Espera a que la Queue quede vacía.
    3. Detén Registrar atributos.
    4. Comprueba que ambos Processors aparecen como Stopped.

    Parada ordenada

    En flujos reales suele detenerse primero la entrada de datos y después los componentes de procesamiento, cuando las colas ya se han vaciado.

    5.18 Limpiar una Queue

    1. Detén los Processors relacionados.
    2. Abre el menú contextual de la Connection.
    3. Selecciona Empty queue.
    4. Confirma la operación.

    Operación destructiva

    Vaciar una Queue elimina sus FlowFiles. No realices esta acción en producción sin comprobar previamente el impacto y la política de recuperación.

    5.19 Buenas prácticas aprendidas

    • Utilizar Process Groups por laboratorio o funcionalidad.
    • Asignar nombres descriptivos.
    • Evitar intervalos de ejecución demasiado pequeños.
    • Revisar las Relationships antes de iniciar el flujo.
    • Observar las colas.
    • Detener primero los Processors de entrada.
    • No registrar datos sensibles.
    • Utilizar Data Provenance para depurar.
    • Documentar el flujo mediante Labels.

    5.20 Errores frecuentes

    El Processor aparece como Invalid

    Posibles causas:

    • existe una Relationship sin conectar;
    • falta una propiedad obligatoria;
    • un Controller Service requerido no está disponible;
    • la configuración contiene un valor no válido.

    La Queue crece continuamente

    Posibles causas:

    • el Processor de destino está detenido;
    • el destino procesa más despacio que el origen;
    • existe un error en el Processor de destino;
    • la planificación es demasiado agresiva.

    No aparecen mensajes en los logs

    Comprueba:

    • que LogAttribute está iniciado;
    • que recibe FlowFiles;
    • que el nivel de log configurado es visible;
    • que estás consultando el contenedor correcto;
    • que Log Payload está activado si esperas ver el contenido.

    Se generan demasiados FlowFiles

    Detén inmediatamente GenerateFlowFile y revisa Run Schedule y Batch Size.

    Laboratorio guiado. Construcción completa

    Parte 1. Preparación

    1. Crea el Process Group LAB 01 - Primer FlowFile.
    2. Añade GenerateFlowFile.
    3. Renómbralo como Generar mensaje JSON.
    4. Añade LogAttribute.
    5. Renómbralo como Registrar atributos.

    Parte 2. Configuración

    1. Introduce el contenido JSON.
    2. Configura una ejecución cada diez segundos.
    3. Activa Log Payload en LogAttribute.
    4. Define el prefijo LAB01.
    5. Auto-termina la Relationship success de LogAttribute.

    Parte 3. Conexión

    1. Conecta ambos Processors.
    2. Selecciona la Relationship success.
    3. Comprueba que no existen errores de validación.

    Parte 4. Ejecución

    1. Inicia el flujo.
    2. Observa las estadísticas.
    3. Detén temporalmente LogAttribute.
    4. Comprueba el crecimiento de la Queue.
    5. Lista los FlowFiles.
    6. Reinicia LogAttribute.

    Parte 5. Observación

    1. Consulta los logs.
    2. Localiza el contenido JSON.
    3. Identifica el UUID.
    4. Abre Data Provenance.
    5. Busca uno de los FlowFiles mediante su UUID.
    6. Examina su recorrido.

    Parte 6. Finalización

    1. Detén el Processor de entrada.
    2. Espera a que la Queue quede vacía.
    3. Detén el Processor de salida.
    4. Comprueba el estado final.

    Reto de ampliación

    Modifica el contenido para generar:

    {
  "sensor": "temperatura-aula-01",
  "valor": 23.7,
  "unidad": "C",
  "edificio": "A"
}

    Después:

    1. Cambia el intervalo de generación a treinta segundos.
    2. Cambia el prefijo de LogAttribute a SENSOR-AULA.
    3. Genera tres FlowFiles.
    4. Localiza uno mediante Data Provenance.
    5. Identifica su UUID, su tamaño y su contenido.

    Resumen

    flowchart LR
    A[GenerateFlowFile] -->|success| Q[(Queue)]
    Q --> B[LogAttribute]
    B --> C((Fin))

    En este capítulo hemos aprendido que:

    • un Processor de origen puede crear FlowFiles;
    • los FlowFiles contienen atributos y contenido;
    • una Connection mantiene una Queue;
    • las Relationships determinan el recorrido;
    • una relación puede auto-terminarse;
    • LogAttribute permite inspeccionar atributos y contenido;
    • Data Provenance permite seguir el recorrido del FlowFile;
    • una parada ordenada evita dejar datos pendientes.

    Este flujo constituye la base para los siguientes capítulos, donde trabajaremos con FlowFiles reales, archivos, atributos, transformaciones y sistemas externos.
